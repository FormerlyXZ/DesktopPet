# 设计规范 — 暖粉奶白手绘风（全局 UI）

> **2026-09-10 起本规范是"全局 UI 规范"，不再只管养成系统。**
> 用户要求把左键功能面板、右键系统面板、设置窗口也统一成这套视觉，于是：
>
> | 曾经 | 现在 |
> |------|------|
> | 本规范只约束养成系统的新 UI；现有设置窗口/右键面板/左键面板**一律不改**，保持冷蓝磨砂玻璃 | **全应用统一**：`hover_menu` / `nurture_panel` / `speech_bubble` / `bubble_panel`（左右键面板）/ `settings_window` + `gif_settings_page` |
> | 第 0.2 节那张"养成 UI vs 现有 UI"的对照表 | **对照物消失了**（两边合流）。该表保留为历史说明，第 0.2 节已改为"全局硬性约束" |
> | 色板定义在 `nurture_icons.py` | 移到 **`src/ui_theme.py`**（唯一来源）；`nurture_icons` 只做转出，四个既有组件因此一行未改 |
>
> 具体到某个组件的规格：悬停菜单看 5.1、养成面板看 5.2、对话气泡看 5.3、
> **左右键面板与设置窗口看 `docs/03-设计规范.md` 第 2、3 节**（已按本规范的色板与手法重写）。

## 0. 设计定位

### 0.1 一句话

把 UI 做成「**贴在屏幕上的、用彩色铅笔画的便签**」，而不是「一个系统设置面板」。

角色本身是暖色系（棕发、奶白衬衫、藏青水手服、粉腮红），所以她的 UI 也必须暖、要软、要圆、要有笔触。

### 0.2 全局硬性约束（原"与现有 UI 的硬性区分"）

> 原本这张表是用来**区分**养成 UI 和现有冷蓝 UI 的。全局统一之后，"区分"这个需求没了，
> 但表里这些**约束本身**（暖白底、暖棕描边、大圆角、不用纯黑、行距、关闭方式…）
> 全部升级为**整个应用都要守的规矩**。

| 维度 | 要求 |
|------|------|
| 底色 | 暖奶白 `rgba(255,249,246,242)`（只有底色带 alpha，描边与文字不透明） |
| 主色 | 奶白 `#FFF9F6` / 樱花粉 `#FFB7C5` |
| 边框 | **2px 暖棕 `#8D6E63` 手绘描边**（次级线 1.5px `#C9AFA6`） |
| 圆角 | 面板 20px ／ 卡片 14px ／ 行 12px ／ 圆按钮 50% |
| 图形语言 | **圆形按钮 + 自绘矢量图标**；**不用 emoji 前缀**（旧版"直角矩形列表项 + emoji 前缀"已废弃） |
| 投影 | 柔和暖色 `rgba(141,110,99,0.18)`，偏移 0/2px（向下偏，模仿纸片） |
| Hover 反馈 | 上浮 1~2px + 粉色光圈/粉描边 + 轻微放大 |
| 字体 | 微软雅黑 13px，行距 1.5，标题 `bold` 且藏青 `#2E4A7D` |
| 文字色 | 主 `#5B4A46`（暖棕黑，**不用纯黑**）／次 `#9E8B86` |
| 关闭方式 | 弹层（悬停菜单/养成面板/对话气泡）**不抢焦点**，靠宽限期或点外部收起；左右键面板**保持原有「获得焦点→失焦即收起」**（那是既有行为，换肤不改行为） |

**禁止事项**：不得出现 `#E3F2FD`、`#42A5F5`、`#BBDEFB` 等冷蓝色值；不得使用 12px 直角矩形列表项；
不得使用 emoji 当图标（`src/nurture_icons.py` 的第 3 级兜底除外 —— 那是"实在画不出"的保险，不是设计手法）。

**机器强制**：`tests/test_nurture_icons.py::test_new_ui_files_avoid_forbidden_colors`
会扫描上表提到的**全部 UI 文件**源码，冷蓝色只能出现在 `FORBIDDEN_COLORS` 定义那一行。

## 1. 色彩系统

### 1.1 色板

| 用途 | 色值 | 说明 |
|------|------|------|
| 面板底 | `#FFF9F6` (240 alpha) | 暖奶白，取代冷蓝底 |
| 面板底-深 | `#FFF1EC` | 分区/次级底 |
| 卡片底 | `#FFFFFF` | 食物卡片 |
| 卡片底-禁用 | `#F7F2F0` + 整卡 45% 不透明 | 库存为 0 |
| **描边** | `#8D6E63` | 暖棕，取自角色发色系；**手绘感的核心** |
| 描边-浅 | `#C9AFA6` | 次级分隔、内线 |
| 主粉 | `#FFB7C5` | 樱花粉：按钮底、进度条 |
| 粉深 | `#F49AB0` | hover / 按下 / 强调 |
| 粉浅 | `#FFE3E9` | 光圈、选中态底 |
| 藏青 | `#2E4A7D` | 水手服领巾色：用于标题/主按钮文字，提供对比度 |
| 领巾红 | `#E5484D` | 角标、红点、心形 |
| 心形粉 | `#FF8FA3` | 好感度进度条填充 |
| **金色** | `#E8B84B` | 红包封口、彩蛋篮、连签里程碑飘字（唯一新增的暖色，不破坏整体色温） |
| 文字主 | `#5B4A46` | 暖棕黑，**不用纯黑** |
| 文字次 | `#9E8B86` | 说明、禁用 |
| 成功 | `#7FB069` | 签到成功、好感度升级、叶子 |
| 阴影 | `rgba(141,110,99,0.18)` | 柔和暖投影 |

> **关于"蓝色"元素**：牛奶盒标签、水手服这类本来该用蓝色的地方一律用**藏青 `#2E4A7D`**。
> 冷蓝（`FORBIDDEN_COLORS` 里那几个 hex）在整个 UI 里**一个都不许出现**，
> `tests/test_nurture_icons.py` 会扫描全部 UI 文件强制这一条。
>
> **代码里的唯一来源是 `src/ui_theme.py`**：本表就是它的注释版。改颜色改那一处，
> `nurture_icons` 会转出旧名字（四个既有组件不动），`ui_theme.app_stylesheet()`
> 会跟着给标准控件上色。

### 1.2 用法约束

- **粉不能铺满**：粉色只用于「可交互元素」和「强调」；大面积底色必须是奶白。满屏粉会廉价且看不清。
- **描边必须在**：所有新组件的外轮廓一律 2px 暖棕描边。有描边才有"画出来的"感觉，去掉描边就退回成普通 Qt 控件。
- **对比度**：文字主色 `#5B4A46` 配奶白底，对比度 ≈ 8.9:1，达标；**不要**把粉色当正文色。
- **半透明**：仅面板底色带 alpha（240/255 ≈ 94%），描边与文字**不透明**，保证任何壁纸下都读得清。

## 2. 字体与排版

| 项 | 规格 |
|----|------|
| 字体族 | `Microsoft YaHei`（与项目全局一致，避免字体缺失） |
| 正文 | 13px / 行距 1.5 / `#5B4A46` |
| 标题 | 13px `bold` / 字距 +0.5px / `#2E4A7D` |
| 数值 | 15px `bold` / `#E5484D`（好感度、连签天数） |
| 说明 | 11px / `#9E8B86` |
| 角标数字 | 10px `bold` / `#FFFFFF` |
| 对话气泡 | 13px / 行距 1.55 / 最大宽 220px |

> **手写体不要用**：中文手写/圆体在 Windows 上无通用字体（华文行楷、方正舒体等不保证存在），强依赖会退化成宋体，比不用更难看。**"手绘感"靠描边、圆角、不对称造型来传达，不靠字体**。

## 3. 造型语言（手绘感的实现手法）

这些是让界面"看起来是手画的"的具体手段，按性价比排序：

1. **粗暖棕描边**（2px，`Qt.RoundCap` + `Qt.RoundJoin`）——效果最直接，优先做
2. **大圆角**——面板 20px、卡片 14px、按钮正圆
3. **不对称圆角**——同一个矩形的四角半径给 `(22, 20, 21, 20)` 这种轻微差异，模仿手绘的不精确；**差异控制在 2px 内**，否则会像 bug
4. **描边不完全贴合填充**——描边路径相对填充路径外扩 0.5px，产生"着色略微溢出线外"的手绘感
5. **投影偏移向下**（0, 2px）而非四周均匀——模仿纸片贴在屏幕上
6. **图标用圆头线帽 + 平涂填充**，不画渐变、不画高光

**禁止**：渐变、玻璃拟态、霓虹发光、立体斜面。这些都会把它拉回"科技感 UI"，与作品气质冲突。

> **这些手法已经全部落成函数**（`src/ui_theme.py`），新组件直接调用即可，别照抄数字：
>
> | 手法 | 函数 |
> |------|------|
> | 1 描边 | `pen(color, width)`（`RoundCap` + `RoundJoin`） |
> | 2 大圆角 | `rounded_path(rect, radii)` + `RADIUS_PANEL/CARD/ROW` |
> | 3 不对称圆角 | `paper_radii(base)` —— 四角差固定 ≤2px |
> | 4 描边外扩 | `paint_path(..., grow=0.5)` |
> | 5 投影 | `paint_shadow()` / `paint_paper()`（偏移向下） |
> | 纸片 / 卡片 / 行 / 圆按钮 / 角标 | `paint_paper` / `paint_card` / `paint_row` / `paint_circle` / `paint_badge` |
>
> 「新面板要和养成面板长得像」的唯一可靠做法是**共用这些函数** —— 照着调一遍数，
> 那份数字迟早会漂。

## 4. 图标规范

### 4.1 三级来源（重要：解决"美术素材从哪来"）

我们**没有**现成的浅粉手绘图标素材。所以图标按三级降级，保证先能跑，后期可无痛替换：

| 级别 | 来源 | 说明 |
|------|------|------|
| 1（优先） | `assets/nurture/icons/{icon_key}.png` | **用户/后期美术自备**，需含 alpha |
| 2（内置） | `src/nurture_icons.py` 用 `QPainter` 矢量绘制 | 13 个食物 + **14** 个功能图标（9 悬停菜单 + 5 左右键面板）各画一版简笔图形 |
| 3（兜底） | emoji / 首字 | 用 `Segoe UI Emoji` 渲染；再失败则画名称首字；再失败画空心圆 |

> 现在这一层是**全应用共用**的图标库（模块名保留 `nurture_icons` 是历史原因，改名不划算）。
> 左右键面板用哪 5 个：`bubble_panel.ITEM_ICONS` —— **菜单项的 `item_id` 不在表里也不会崩**，
> 会自动退化成"名称首字"，所以在 `pet_window` 里加新菜单项时不需要改面板。
> 阶段 A~D 全部走第 2 级，界面先完整可用；后期你补了 PNG，放进目录即自动覆盖，**不需要改代码**。
> `assets/nurture/icons/README.txt` 里写了文件命名与规格要求，可直接照着画。

**看内置图标长什么样**（改图标前后都该跑一次）：

```bash
python -m src.nurture_icons _icons_preview.png
```

会生成两张对照图：`_icons_preview.png`（44px 带标签）与 `_icons_preview_20px.png`
（**20px 真实使用尺寸、无标签**）。第二张是判断"小尺寸下认不认得出"的唯一依据 —— 只看大图必然误判。

## 5. 组件规格

### 5.1 悬停菜单 `HoverMenu`

```
        ┌──────────────────────────────────────┐   ← 奶白胶囊底 20px 圆角
        │  (🍙)  (🎁)  (📅)•  (💗)  (💬)  (⚙)  │      2px 暖棕描边
        └──────────────────────────────────────┘      暖色投影
              ↑     ↑     ↑
           喂食  送礼  签到（右上角红点•）
```

| 项 | 规格 |
|----|------|
| 形状 | 横向胶囊（圆角 = 高度/2） |
| 内边距 | 8px |
| 按钮 | 正圆，直径 `clamp(36, pet_height × 0.11, 52)` px（桌宠 300px→36px，500px→52px） |
| 按钮间距 | 8px |
| 图标 | 20px，居中 |
| 默认态 | 底 `#FFF1EC`，描边 2px `#8D6E63` |
| Hover 态 | 底 `#FFE3E9`，描边 `#F49AB0`，上浮 1px，外圈 3px `rgba(255,183,197,0.5)` 光圈，整体 1.04 倍 |
| 按下态 | 底 `#F49AB0`，下沉 1px |
| 不可用 | 底 `#F7F2F0`，描边 `#C9AFA6`，图标 45% 不透明；**仍可点击**（点击后出说明气泡） |
| 红点角标 | 直径 9px 正圆 `#E5484D` + 1.5px 奶白描边，位于按钮右上角外侧 |
| 提示条 | 按钮 hover 时浮出小标签（奶白底 + 暖棕描边 + 13px 文字），150ms 淡入；**放在胶囊背离人物的那一侧**（菜单恒在人物下方 → 标签恒朝下），与胶囊固定隔 6px |
| 定位 | 恒定贴人物**下方**、水平居中对齐，胶囊顶边与人物底边间隔 8px；左右越界 → 水平夹紧；横排比屏幕还宽 → 竖排；整体夹紧到屏幕内 |
| 弹出动效 | 从**下方**滑入 12px + 淡入，200ms `OutCubic` |
| 收起动效 | 反向滑出 + 淡出，160ms `InCubic` |
| **焦点** | **`WindowDoesNotAcceptFocus`，绝不 `activateWindow()`**，也不实现 `focusOutEvent` 收起 |

> **落位只有两个自由度**（2026-09-10 第二次修订，取消"上方优先 + 上下左右逐级兜底"）：
> 恒定贴人物下方 → 横排放不下整块屏幕宽时转竖排 → 整体夹紧进屏幕可用区。
> 为什么取消按屏幕位置挑方位：菜单每次都从同一侧冒出来，用户才有可预期的肌肉记忆；
> 人物一往上拖、菜单就改从另一侧钻出来，同一套按钮在屏幕上跳来跳去反而更难用。
>
> **代价（明确接受）**：人物沉到屏幕底部时，菜单会被屏幕底边顶上去、压住她下半身。
> 取舍是"遮住她还能把她拖上来，按钮掉到屏幕外就是彻底点不到了"。
>
> 「间距 8px」指的是**胶囊边缘**到人物边缘的距离，不是窗口边缘 —— 窗口在胶囊外还留了 6px 投影空间
> 与 26px 提示条预留带，拿窗口边缘去量会凭空多出 6~32px。竖排与提示条朝向都**不改变窗口尺寸**，
> 但朝向会改胶囊在窗口内的纵坐标，所以 `plan_placement()` 里**先定朝向再算落位**。

### 5.3 对话气泡 `SpeechBubble`

```
                 ┌────────────────────────┐
                 │  唔，好吃。            │  ← 奶白底 14px 圆角
                 └───────────┬────────────┘     2px 暖棕描边
                             ▼                  暖色投影
                          （头顶）
```

| 项 | 规格 |
|----|------|
| 宽度 | 自适应 `[120, 220]` px |
| 圆角 | 14px |
| 尾巴 | 底边居中的等腰三角，**宽 14px、高 8px**，与主体合并为一个 `QPainterPath` 后再描边（避免接缝出现内线） |
| 底色 | `rgba(255,249,246,240)` |
| 描边 | 2px `#8D6E63`，圆头圆角连接 |
| 内边距 | 上下 10px，左右 12px |
| 文字 | 13px / 行距 1.55 / `#5B4A46` / 自动换行 / 最大 4 行（超出加省略号） |
| 投影 | 0/3px，模糊 10px，`rgba(141,110,99,0.20)` |
| 定位 | 尾巴尖对准 `人物窗口顶部 + 高度 × 0.14`（可在设置里调 `bubble_anchor_ratio`），气泡水平居中于人物；左右越界 → 水平夹紧；上方越界 → 翻到人物**下方**，尾巴朝上 |
| 出现动效 | 从下方 8px 滑上 + 淡入，180ms `OutCubic` |
| 停留 | 默认 3500ms（设置可调 2000–8000ms） |
| 消失动效 | 反向滑下 8px + 淡出，220ms `InCubic` |
| 同时数量 | **最多 1 个**；新台词到来先停旧计时器再替换内容 |
| 鼠标 | **完全穿透**（`WindowTransparentForInput` + `WA_TransparentForMouseEvents`），不可点击、不可选中 |
| 焦点 | **绝不获取焦点**（`WindowDoesNotAcceptFocus` + `WA_ShowWithoutActivating`） |
| 层级 | 与桌宠同为 TOPMOST，但用 `_force_raise_topmost` 确保压在人物之上 |

**多行文本的气泡形态**：文本换行后气泡自动增高，但**尾巴始终水平居中**，不随文本块偏移。

> **落地时补的三条**（阶段 E，写在实机验证之后）：
>
> 1. **翻到人物下方时，尾巴尖改对准「人物底边」**，不再用头顶的 14%。
>    照字面实现会让气泡压在人物身上 —— 她的头就在窗口高 14% 处，
>    气泡放她下方却把尾巴尖指到头顶，主体必然盖住她。
> 2. **入场与退场方向必须相反**：入场从「靠近人物的一侧」滑出来（从上方的气泡 → 从下方滑上），
>    退场往回滑。写反了会变成"气泡从头顶往下掉"，而且刚出现的那一刻位置差整整 8px。
> 3. **动效不用 `panel_animator`**：它的位移硬编码 40px，而这里要求 8px
>    （与 `HoverMenu`/`NurturePanel` 同样的理由，三个组件各自管自己的动效参数）。

## 7. 布局与遮挡规则

这是桌宠类 UI 最容易做脏的地方，必须定死：

| 优先级 | 元素 | 位置 | 规则 |
|--------|------|------|------|
| 1 | 人物本体 | 用户拖放的位置 | 绝对不能被遮挡 |
| 2 | 对话气泡 | 人物**头顶**上方（在人物窗口内的预留区） | 尾巴对准窗口高 14% 处；上方空间不足 → 翻到下方 |
| 3 | 悬停菜单 | 人物**下方**、水平居中 | 胶囊距人物 8px；**固定下方，不随屏幕位置翻面**；左右不足 → 水平夹紧；极窄屏 → 竖排 |
| 4 | 养成面板 | 人物**左侧** | 面板在左、菜单在下、气泡在头顶，三者互不占位；左侧不足 → 翻右 |
| 5 | 现有功能/系统面板 | 由现有逻辑决定 | 打开时**强制收起**悬停菜单与养成面板 |

**互斥矩阵**（`NurtureController` + `PetWindow` 仲裁器共同保证）

| 已显示 \ 要显示 | 悬停菜单 | 养成面板 | 对话气泡 | 功能面板 | 系统面板 | 设置窗口 |
|------------------|----------|----------|----------|----------|----------|----------|
| 悬停菜单 | — | 收起菜单 | **可共存** | 收起菜单 | 收起菜单 | 收起菜单 |
| 养成面板 | — | — | **可共存** | 收起面板 | 收起面板 | 收起面板 |
| 对话气泡 | 共存 | 共存 | 替换 | 共存 | 共存 | 共存 |
| 设置窗口 | 抑制弹出 | 抑制弹出 | 抑制新台词 | 现有逻辑 | 现有逻辑 | — |

- 对话气泡与菜单/面板**允许共存**：气泡锚在人物窗口**内**的头顶预留区（尾巴对准 14%），
  悬停菜单贴在窗口**外**下方 8px，面板在左侧 —— 一两行台词根本碰不到。
  菜单改到下方后与气泡离得更远了（气泡在头顶、菜单在脚下），重叠概率进一步下降。
  真出现重叠时**以菜单在上为准**（菜单是用户主动操作，且 `_force_raise_topmost` 最后调用），
  并优先让气泡收短（`bubble_max_width` 调宽），**不要**给菜单再加躲避逻辑。
- 设置窗口可见时：**抑制**悬停菜单与养成面板弹出（避免误触），气泡不再新增
- 桌宠被拖动时：所有弹层跟随移动（现有 `mouseMoveEvent` 已有此逻辑，把新面板加进去）

## 9. 文案语气规范（视觉之外的"软设计"）

字要少、要口语、要留白。规则见 01 文档 7.1（三档语气 + 七条硬禁区），这里是排序与格式要求：

| 要求 | 说明 |
|------|------|
| 长度 | 单条台词 **≤ 18 个汉字**（气泡最大宽 220px，超过两行就显得吵） |
| 标点 | 用「。」「…」「，」；**不用**感叹号堆叠、不用颜文字（与作品气质不符） |
| 不说教 | 不出现「你应该」「别忘记」「记得」。她不是提醒事项 |
| 不用系统口吻 | 不出现「已保存」「操作成功」「获取失败」——这类信息走 UI 与角标，不走她的嘴 |
| 名字 | 她称呼用户不用"主人"；作品里她直呼「西片」，这里建议用**中性称呼或直接省略主语**（如「又在忙呀」），避免代入感错位 |
| 允许沉默 | 台词池可以为空 → 那次就不说话。**不必每次都有台词** |

## 10. 边界与适配

| 情况 | 处理 |
|------|------|
| 桌宠很小（高度 250px） | 菜单按钮按公式缩到 36px（下限）；**气泡字号保持 13px 不变**（可读性优先） |
| 桌宠很大（高度 700px） | 按钮封顶 52px；面板宽度不变（不跟着放大，否则显得空） |
| 高 DPI（150%/200%） | 图标与描边按 `devicePixelRatio` 渲染；`QPen` 宽度用逻辑像素，Qt 自动缩放 |
| 深色壁纸 | 奶白底 + 暖棕描边对比度足够；不使用纯白底（会过曝） |
| 浅色壁纸 | 靠 2px 描边与投影区分；不使用纯浅粉底（会糊在壁纸上） |
| 多显示器 | 所有弹层定位优先用**光标所在屏幕**（沿用现有 `app.screenAt(pos)` 逻辑） |
| 屏幕边缘 | 统一走"翻转 → 夹紧"两步兜底（同现有 `show_at`） |
| 系统缩放改变 | 监听 `screenChanged` 重新计算尺寸 |

## 11. 验收自检清单（美术部分）

- [ ] 养成 UI 中**不出现**任何冷蓝色值（`#E3F2FD` / `#42A5F5` / `#BBDEFB`）

- [ ] 面板、菜单、气泡三者不会互相遮挡

- [ ] 深色/浅色壁纸下文字都清晰可读

- [ ] 所有动效走缓动曲线，无线性动画
- [ ] 单条台词 ≤ 18 字，且不含系统口吻词汇
