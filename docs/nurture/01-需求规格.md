# 需求规格 — 养成高木同学（Nurture）

> 本文件是「养成系统」的主需求文档。配套文档见同目录 `02-技术方案.md`、`03-设计规范.md`、`04-开发步骤.md`。
> 参考现有实现：`docs/01-需求规格.md`（桌宠本体）、`src/gif_character.py`（Q版交互状态机）、`src/bubble_panel.py`（现有菜单面板）。

---

## 0. 定位与范围

### 0.1 一句话定位

在现有 Q版高木同学桌宠之上，增加一层「**轻养成 + 陪伴对话**」：

- 鼠标在人物身上**停留片刻**，自动弹出养成选项菜单（签到 / 喂食 / 送礼 / 好感度 / 设置）
- 通过**签到、陪伴时长、彩蛋**获得食物与礼物
- 送出后播放对应反应动画，并用**对话气泡**说一句话
- 平时她会在**待机、感知到你在做什么、特定时间**时主动说话

### 0.2 只作用于 Q版高木同学

养成系统**仅对 GIF 角色（Q版高木同学）生效**。

- 角色为「默认服装（PNG）」时：养成系统整体休眠——不弹菜单、不说气泡、不计时、不签到（数据保留不丢）
- 切回 Q版时：立刻恢复，不重播启动序列以外的任何强制流程
- 理由：PNG 默认服装的交互行为是项目的回归红线（`CLAUDE.md` 明确「默认服装行为不可改动」）

### 0.3 非目标（本期不做）

| 不做 | 原因 |
|------|------|
| 数值衰减 / 饥饿掉血 / 生病 / 死亡 | 已确认走「轻养成」，不给用户压力 |
| 多角色养成 / 换装 | 只服务 Q版高木同学 |
| 联网账号、云同步、排行榜 | 保持纯本地 |
| 用 AI 生成台词 | 已确认走纯本地台词库；架构上预留可插拔的台词来源接口 |
| 读取剪贴板内容做台词 | 已确认**不启用**（隐私） |
| 补签 / 签到防作弊强校验 | 轻养成无经济价值，只做「时间回退不刷连签」的最低保护 |

### 0.4 设计原则（贯穿全文的取舍依据）

1. **不打扰优先**：桌宠的第一身份是「陪着你」，任何新元素都必须能一键关闭、能自动退场、绝不抢焦点、绝不拦截鼠标。
2. **只给正反馈**：不喂食不会变差、不理她不会有惩罚。所有数值只升不降（连签中断除外，且中断也只重置不多扣）。
3. **不评判用户**：她能知道「你在用 VS Code」，但不评论你写的东西；能知道「你在打游戏」，但不作道德评判。
4. **可拆可关**：养成、气泡、行为感知分别是独立可关的开关，任意一项关掉不影响其余功能与桌宠本体。
5. **素材驱动**：食物、台词、动画映射全部走外部 JSON/目录，用户不写代码就能增删。

## 2. 数值系统

### 2.1 三项状态

| 状态 | 范围 | 变化 | 用途 |
|------|------|------|------|
| **好感度** | 0 起，无上限（软上限 1000） | 只增不减 | 解锁台词组、互动动作、菜单项 |
| **食物库存** | 按食物档位分别计数 | 获取 +／送出 − | 可送出的东西 |
| **连签天数** | 0 起 | 连续签到 +1；断签归 1 | 提升签到产出品质 |

**明确不做**：饥饿值、心情值、体力值、经验条、等级惩罚。理由见 0.4 原则 2。

### 2.2 好感度

**来源**

| 来源 | 增量 | 说明 |
|------|------|------|
| 送出「普通」食物 | +1 | |
| 送出「稀有」食物 | +2 | |
| 送出「珍贵」食物/礼物 | +4 | |
| 连签里程碑（3 / 7 / 14 / 30 天） | +5 / +10 / +20 / +50 | 每达成一次给一次 |
| 首次签到（第一天） | +2 | 引导用 |

**每日好感度获取上限**：默认 **20/天**（防止连点刷满）。达到上限后仍可送出食物（动画与台词照常），但不再加好感度，且气泡会说一句「今天已经很开心了」。

**好感度等级与解锁**（阈值可配置）

| 好感度 | 称号 | 解锁 |
|--------|------|------|
| 0 | 认识 | 默认台词组 |
| 50 | 同桌 | 解锁「待机闲聊」台词组 |
| 120 | 朋友 | 悬停菜单新增「陪她聊聊」项（主动触发一句台词） |
| 250 | 要好 | 解锁「小得意」语气台词 + 节日台词组 |
| 450 | 特别 | 悬停菜单新增「摸头」互动（播 `害羞 2` + 专属台词） |
| 700 | 最重要的人 | 解锁「深夜谈心」台词组 + 菜单项全部解锁 |

> 阈值集中在 `assets/nurture/levels.json`，用户可改。

### 2.3 库存上限

| 档位 | 单类上限 | 总上限 |
|------|----------|--------|
| 普通 | 20 | |
| 稀有 | 10 | |
| 珍贵 | 5 | |

达到上限时获取失败，气泡提示「拿不下啦」，并**不浪费**该次获取机会（改为顺延到次日或提示用户）——具体见 6.4。

## 3. 食物与礼物

### 3.1 两类可送出物

| 类型 | 影响 | 动画倾向 |
|------|------|----------|
| **食物** | +好感度，动画为"收下并害羞/开心" | 捧食物类 |
| **礼物** | +好感度（增量更高），动画为"惊喜/庆祝" | 道具类 |

> 轻养成下两者数值效果接近，区分主要是**叙事与动画风味**：食物是日常投喂，礼物是有仪式感的惊喜。送礼有独立的每日上限（默认 3 次/天），喂食不限次（但受好感度每日上限约束）。

### 3.2 建议清单（食物母题取自校园/夏日祭/情人节等动画常见场景）

**已写入 `assets/nurture/items.json`，可直接增删改名**，不涉及代码；改 `anim` 字段即换动画。
（`items.json` 里额外带了一个 `icon_key` 字段，对应 `nurture_icons.py` 的矢量图标；找不到时会走
「用户 PNG 图标 → 内置矢量 → emoji/首字」三级降级，所以**新增食物也不会出现"没有图标"的情况**。）

### 3.3 兜底链（必须实现）

素材库**没有专门的"吃东西"动画**，所以每个食物都要能安全降级：

```
食物自身 anim
  → 若该动作名在 GifRegistry 中不存在
食物类型默认 anim（食物→"笑"，礼物→"点赞"）
  → 若仍不存在
全局兜底 anim（"害羞 2"）
  → 若仍不存在
不播动画，只出对话气泡（绝不可崩溃、绝不可黑屏）
```

> 用户日后若补做了「吃」的 GIF，只需命名成 `takagi_吃_时间戳.gif` 放进素材库，然后在 `items.json` 里把想替换的食物的 `anim` 改成 `吃` 即生效，无需改代码。

### 3.4 已知素材缺陷（实现时注意）

| 素材 | 问题 | 处理 |
|------|------|------|
| `冒泡 2` | 画面含**不透明黑色边缘块**（"从屏幕边探头"的场景），叠加在桌面上会显出一块黑色矩形 | 默认不进养成动画池；若用户手动选用，不作特殊处理 |
| `睡觉(普通)` | 同上，含不透明的"桌面/桌沿"黑块 | 已在夜间待机使用，沿用现状，本期不动 |
| `玫瑰` | 首帧无玫瑰，中段才举起 | 无影响（程序播完整动画） |

## 4. 食物获取途径

已确认启用全部四条途径（**不含**"无限免费"）。所有数值均为默认值，集中在配置文件里可调。

### 4.1 每日签到

| 规则 | 内容 |
|------|------|
| 频次 | 每天限 1 次 |
| 基准 | **本地日期**（`QDate.currentDate()`），跨天以 00:00 为界 |
| 基础产出 | 普通食物 ×2 |
| 连签判定 | 与上次签到日期相差 **1 天** → 连签 +1；相差 **0 天** → 今日已签，拒绝；相差 **≥2 天** → 连签重置为 1 |
| 里程碑奖励 | 连签第 3 / 7 / 14 / 30 天：额外给 1 个稀有（第 3 天）/ 珍贵（第 7 天）/ 珍贵（第 14 天）/ 珍贵（第 30 天），并加好感度（见 2.2） |
| 表现 | 播 `庆祝`（彩带礼花）→ 对话气泡报出「连签 N 天，这是今天的份」+ 好感度进度提示 |

**入口**（三处，任一均可）

1. 悬停菜单的「签到」项（今日未签时带**红点角标**）
2. 启动后若今日未签 → 首次弹出悬停菜单时该项高亮 + 一次气泡提醒（每天最多提醒 1 次）
3. 系统托盘右键菜单「今日签到」（旁边还有只读的「养成状态」；养成关闭或非 Q版时这两项不显示）

> 一次点击**只出一个对话气泡**：库存满 > 里程碑 > 普通签到，取第一个有台词的。
> 连着说三句会被后一句顶掉（对话气泡是替换不是叠放），最后只剩一句无关紧要的。

### 4.2 陪伴兑换（把"你陪我工作"变成奖励）

复用现有 `InputMonitor`，**不新增依赖**。

| 途径 | 规则 | 每日上限 |
|------|------|----------|
| 在电脑前时长 | 累计前台活动时间每满 **60 分钟** → 普通食物 ×1 | 3 |

> 时间统计口径：仅当**键鼠有活动**时才累加（复用 `any_activity`），纯挂机不计入。累计值跨天清零。
> 实现口径（2026-09-10 定）：`any_activity` 只告诉我们"刚刚有输入"，
> 用**相邻两次输入的时间差**近似这一段时长，并**单次截断到 5 秒** ——
> 否则挂机 3 小时后的第一次鼠标移动会一口气折算出 180 分钟，直接换出 3 份食物。
> 进度每分钟回写一次存档（内存累加，不碰 I/O）。

| 途径 | 规则 | 每日上限 |
|------|------|----------|
| 打字量 | 每累计 **2000 次按键** → 普通食物 ×1 | 2 |

> `InputMonitor` 目前只有 `key_pressed` 信号（每次按键一发）。按键计数放在
> `NurtureController` 里（拉模型），没有改那个既有文件 —— 详见 02 文档 4.10/4.11。

兑换达成时：播 `点头` + 气泡「你敲了好久了，休息一下，这个给你」。

> **同一份进度只兑一次**：结算时同时看"今日进度"和"今日已兑换个数"。
> 少看后者会让每次心跳都能再兑一个 —— 表现是"挂着不动，食物自己一直涨"（阶段 F 修的真 bug）。

### 4.3 彩蛋掉落

| 触发 | 概率 / 条件 | 产出 |
|------|-------------|------|
| 整点报时 | **每个小时掷一次**，**25%** 概率 | 普通食物 ×1，每天最多 **3** 次 |
| 长时间待机 | 连续 AFK 超过 **10 分钟**（在现有 AFK 逻辑上叠加） | 稀有食物 ×1，每天最多 1 次 |
| 节日/纪念日 | 命中 `assets/nurture/events.json` 中的日期 | 珍贵礼物 ×1 + 专属台词 |
| 首次使用 | 首次启动养成系统的当天 | 珍贵食物 ×1（引导用） |

> 文档原文是":00 时 25%"，但心跳是 60 秒一次、起跳时刻由进程启动时间决定，
> 卡"分钟数 < 5"会大概率整天掷不到，所以实现改成"观察到新的一个小时就掷一次"
> —— 玩家感受到的仍然是"每小时可能掉一次"。
> 每天 3 次的上限是**实现补的**（原文没写，但挂机一整天能白拿十几次）。
> 库存满时该次**不发放也不补发**（01 文档 4.4），但当天次数照样算用掉。

**内置节日表**（`events.json`，可扩充）

| 日期 | 事件 | 产出 |
|------|------|------|
| 2/14 | 情人节 | 巧克力 + 专属台词组 |
| 7/7 | 七夕 | 玫瑰 + 专属台词组 |
| 12/25 | 圣诞节 | 生日蛋糕 + 专属台词组 |
| 1/1 | 新年 | 压岁钱 + 专属台词组 |
| 用户生日（设置里填） | 生日 | 生日蛋糕 + 专属台词组 |

### 4.4 边界与异常

| 情况 | 处理 |
|------|------|
| 用户把系统时间往前调 | **不刷连签**：若检测到「今天 < 上次签到日」，只提示「时间好像不太对」，不发放不重置 |
| 系统时间往后调很多天 | 连签正常重置为 1，气泡改为「好久不见」语气 |
| 库存已满时获得 | 该次获取**不发放**，气泡提示「拿不下啦，先送掉一些吧」；彩蛋类不补发（避免复杂化） |
| 跨天时程序正在运行 | 由一个每分钟的检查计时器发现日期变更，刷新「今日是否已签」状态与角标 |
| 首次运行（无存档） | 初始化存档，连签 = 0，不播任何"欢迎回来"台词；用户第一次签到才开始计连签 |

## 5. 悬停菜单

### 5.1 触发

| 项 | 规则 |
|----|------|
| 触发方式 | 鼠标**停留在人物实体区域**上 |
| 触发延迟 | 停留 **600ms** 后弹出（避免鼠标扫过就弹，也避免与「悬停→害羞」动画抢第一眼） |
| 位置 | 恒定贴在人物**下方**（水平居中对齐），**不按屏幕位置挑方位**；横排比整块屏幕还宽（极窄屏）才转竖排；最后整体夹紧到屏幕可用区（**不要**复用现有面板的定位 —— 悬浮条尺寸与面板差一个数量级）。<br>⚠️ 初版照抄 `BubblePanel` 贴右侧，一改贴上方，实机验收后二改为**恒定下方**（2026-09-10）：菜单位置固定，用户才有稳定的肌肉记忆 |
| 每屏一次 | 同一次悬停只弹一次；鼠标离开后再次悬停需重新计时 |
| 抑制条件 | 设置窗口开着 / 系统面板(BubblePanel)开着 / 正在播放不可打断的动画 / 正在拖拽 / 角色不是 GIF / 养成系统被关闭 → 一律不弹 |

### 5.2 菜单项

| 项 | 可用条件 | 行为 |
|----|----------|------|
| 🍙 **喂食** | 库存中有食物 | 打开养成面板（食物页） |
| 🎁 **送礼** | 库存中有礼物且今日送礼次数未满 | 打开养成面板（礼物页） |
| 📅 **签到** | 今日未签 | 立即签到（见 4.1）；今日未签时带**红点角标** |
| 💗 **好感度** | 始终 | 打开养成面板（状态页：好感度 / 称号 / 连签 / 今日进度） |
| 💬 **陪她聊聊** | 好感度 ≥ 120 | 立即主动说一句台词 |
| 🤚 **摸头** | 好感度 ≥ 450 | 播 `害羞 2` + 专属台词 |
| ⚙ **设置** | 始终 | 打开设置窗口（复用现有 `SettingsWindow`） |

- 不可用项**置灰**而非隐藏（让用户看到"还能解锁什么"），并在悬停/长按时用气泡说明原因（如「今天送过三个啦」）
- 菜单**不显示**「退出」——退出仍在右键系统面板，避免误触

### 5.3 收起与宽限期（关键实现点）

**问题**：悬停菜单是独立窗口。鼠标从人物移到菜单上时，`PetWindow` 会收到 `leaveEvent`。现有 `handle_mouse_leave()` 会立刻把角色从「害羞」切回「加油」，同时菜单自身如果绑定了 `focusOutEvent` 会直接收起——**用户根本点不到菜单**。

**要求**

1. 鼠标离开人物后 **不立即**收起菜单，进入 **350ms 宽限期**
2. 宽限期内鼠标进入菜单 → 取消收起，菜单保持
3. 宽限期结束仍不在菜单上 → 菜单淡出收起
4. 鼠标**从菜单移回人物**同样要宽限，避免菜单闪断
5. 宽限期内**不切换角色动画**（保持 `HOVER_IDLE` 害羞），避免"她一边害羞一边突然加油"

> 现有 `_toggle_function_panel()` 是"点击切换"，与悬停菜单的"停留弹出"是两套逻辑，互不干扰，但**同一时刻只能有一个面板可见**（见 5.4）。

### 5.4 与现有交互的优先级仲裁（必须实现，否则必然打架）

现有 Q版交互已经占用了悬停、单击、双击、长悬停。冲突与裁定如下：

| 场景 | 现有行为 | 新行为（裁定） |
|------|----------|----------------|
| 悬停进入 | 播 `害羞 2`（HOVER_IDLE） | **保留**。600ms 后叠加弹出悬停菜单，人物继续害羞 |
| 悬停 3 秒 | 播 `问号` | **菜单已弹出时取消问号**（避免"菜单开着她在旁边冒问号"的杂乱）。菜单未弹出时保留原行为。以设置项「菜单弹出后禁用长悬停问号」控制，默认开 |
| 单击人物 | 播 `惊吓` + 弹出左键功能面板(clipboard) | **保留不变**，菜单开着时也一样。**2026-09-10 修订**：原裁定"悬停菜单可见时单击 = 只收起悬停菜单"已作废（见下方修订说明） |
| 双击人物 | `生气` → `哭 1`（链式不可打断） | **保留不变**。链式播放期间不弹悬停菜单、不弹气泡 |
| 右键 | 弹出系统面板 | **保留不变**；弹出时收起悬停菜单 |
| 拖拽 | 移动窗口 | **保留不变**；拖拽期间与拖拽后 400ms 内不弹悬停菜单 |
| 点击面板按钮/关闭设置 | `点头` / `摇头` | 保留不变 |
| 喂食动画播放中 | — | 视为不可打断，期间不弹任何面板、不弹气泡 |

> 实现上建议在 `PetWindow` 增加一个**统一的面板仲裁器**：`_any_popup_visible()` / `_hide_all_popups(except=None)`，所有面板的显示与隐藏都过这一个口子。现有 `_toggle_function_panel` / `_toggle_system_panel` 里的互斥判断已经是一半的雏形，直接收拢即可。

#### 5.4.1 修订说明（2026-09-10 实机反馈）

上表「单击人物」那一行的**原裁定「悬停菜单可见时，单击 = 收起悬停菜单」已作废**，原因是它在实机上的表现与设计意图相反：

- 设计意图是"点偏了想收菜单时别弹面板"，实际效果却是**"鼠标一放到人物身上弹出喂养菜单之后，就再也点不出功能面板了"** —— 必须先等菜单自己消失。而 Q版默认玩法是"悬停看菜单、单击开功能面板"，这条裁定把两者变成了互斥。
- **同一个局面下右键是能弹出系统面板的**（`_toggle_system_panel()` 走仲裁器、顺带收起菜单），左右键行为不一致本身就是 bug。
- 修订后的规则只有一句：**单击永远等于"惊吓 + 弹出功能面板"**，悬停菜单开着时也一样，只是顺带被仲裁器收起（互斥矩阵「同一时刻只有一个弹层可见」仍然成立）。

因此 12 节回归红线里"除 5.4 明确裁定的 3 条"应读作 **2 条**（「菜单弹出后取消长悬停问号」「喂食动画播放中不弹任何面板」）。

## 6. 养成面板与喂食流程

### 6.1 养成面板

从悬停菜单进入，三个页签（或分段）：**食物 / 礼物 / 状态**。

- **食物页**：网格卡片，每格显示食物图标 + 名称 + **库存数量角标**
- **礼物页**：同上
- **状态页**：好感度心形进度条 + 称号 + 连签天数 + 今日已获好感度/上限 + 各获取途径的今日进度
- 库存为 0 的格子置灰，点击时气泡说明获取途径（「今天还没签到哦」）
- 面板顶部一行常驻显示：`♥ 好感度 128 / 连签 5 天`

### 6.2 完整流程时序

```
鼠标停留人物 600ms
   └→ 悬停菜单弹出（人物保持 害羞 循环）
        └→ 点「喂食」
             └→ 悬停菜单收起，养成面板弹出（食物页）
                  └→ 点某个食物（库存 > 0）
                       ├→ 养成面板淡出
                       ├→ 扣库存、加好感度（受每日上限约束）
                       ├→ 角色播放映射动画（单次，不可打断）
                       ├→ 对话气泡弹出专属台词（与动画并行）
                       └→ 动画结束 → 气泡自然消失 → 回到 IDLE（或悬停态）
```

### 6.3 表现细节

| 环节 | 要求 |
|------|------|
| 动画播放 | 单次播放（`_play_once` 语义），播放期间视为**不可打断**，与现有「双击第二步」同等级 |
| 好感度提升 | 状态页数值滚动增长（Tween 0.6s），并在角色头顶**飘一个心态 ♥**（可选，见 03-设计规范） |
| 台词 | 见第 7 节；每条食物可在 `items.json` 里配**专属台词**，缺省时从 `feed_done` 场景池随机 |
| 播放结束 | 回到 IDLE；若鼠标仍在人物上，回到 HOVER_IDLE 并重新计时 |
| 连点防护 | 动画播放中面板不可再点（面板已淡出）；动画结束 +300ms 内不接受新的送出 |

### 6.4 送出失败的分支

| 情况 | 表现 |
|------|------|
| 库存为 0 | 不扣、不播，气泡：「这个已经吃完了呢」+ 提示获取途径 |
| 好感度到达每日上限 | 正常播放动画与台词，但**不加好感度**，额外跟一句「今天已经很开心了」 |
| 今日送礼次数已满 | 礼物页顶部提示，点击气泡说明 |
| 动画动作名全部兜底失败 | 只出气泡，不崩溃 |

## 7. 对话气泡（台词系统）

### 7.1 语气体系 —— 「捉弄」的分寸（**你最拿不准的一点，这里是完整建议**）

**我的判断：不要把"捉弄"做成默认语气，改成"温柔的观察"为默认，"捉弄"降级为可选语气包。**

理由：

1. 作品里的捉弄之所以好看，是因为它有一个**明确的叙事前提**——高木喜欢西片，西片被捉弄后其实很开心，而且这是**虚构的、有结局的、双方都乐意的**关系。
2. 桌宠面对的是**正在真实工作/学习的人**。用户看到"她注意到我在干什么然后调侃我"，很容易从「被陪伴」滑向「**被监视**」或「**被评判**」——尤其在你疲惫、拖延、搞砸了的时候。
3. 一台一直在你桌面上的程序，**它说的话会被听到几百上千次**。尖锐的话第一次好笑，第五十次是骚扰。温柔的话才经得起重复。
4. 你自己已经察觉到了（"再强行捉弄不太好吧"），这个直觉是对的，我建议顺着它走。

**具体设计：三档语气**

| 语气 | 内容 | 默认占比 |
|------|------|----------|
| `gentle` 温柔 | 关心、打气、闲聊、"我在呢"、天气/时间/日常小事 | **主基调** |
| `proud` 小得意 | 她自己的小情绪：被喂了很开心、被夸了得意、你太久没理她有点小寂寞（但不指责） | 次要 |
| `tease` 调皮 | 轻度捉弄：**只针对"客观、无害、可自我解耦"的现象** | 少数，且可关 |

**设置项**：`捉弄频率：关闭 / 偶尔（默认） / 正常`，对应 `tease` 的抽取概率 0% / 15% / 35%。

**`tease` 的硬性禁区**（写死在代码里，用户无法开启）：

| 禁区 | 说明 |
|------|------|
| 不评论工作/学习内容 | 只知道"你在用 VS Code"，不知道也不提你在写什么。台词上限到「又在忙呀」这个抽象层级 |
| 不在专注时打扰 | 检测到高频打字 / 连续工作 > 90 分钟 → 只允许 `gentle` 打气，禁止 `tease` |
| 不质问、不抱怨 | 永远不说「你怎么这么久不理我」「你去哪了」 |
| 深夜只关心 | 23:00–06:00 期间禁用 `tease`，只允许关心/催睡 |
| 不做评判 | 不说「又在打游戏」「别摸鱼了」这类道德评价 |
| 每天有额度 | `tease` 台词 **24 小时上限 6 条** + 同一场景 **30 分钟冷却** |
| 一键静音 | 提供「今天不要捉弄我」开关，切到纯关心模式，次日自动恢复 |

> 这七条建议同时作为**验收标准**（见第 12 节）：任何 `tease` 台词在禁区条件下都不得出现。

### 7.3 防打扰规则（对**所有**主动台词生效）

主动台词（非用户直接触发的那类，如 `idle_random`、`detect_*`、`time_*`）统一受以下约束：

1. **全局最小间隔**：两条主动台词之间至少 **90 秒**
2. **专注保护**：检测到高频打字或前台是会议软件 → 主动台词暂停（用户主动触发的例外）
3. **游戏/全屏保护**：检测到前台是全屏应用 → 主动台词暂停（避免遮挡和打扰）
4. **气泡不叠加**：同一时刻只有一个对话气泡，新的到来则替换旧的
5. **不抢焦点**：对话气泡窗口必须 `WA_ShowWithoutActivating`，且**默认鼠标穿透**（`WA_TransparentForMouseEvents`），绝不打断用户当前操作
6. **可关**：设置里「主动说话」总开关，关掉后仅保留用户交互触发的台词
7. **免打扰时段**：可配置（默认不设），时段内完全静默

> **两处仲裁（实现时定的，改过要一起改回来）**
>
> - 第 2 条与 `detect_typing` / `detect_app_*` 自相矛盾：这些台词的触发条件**就是**
>   "你在打字" / "你在开会"。裁定为**就事论事的观察类台词放行**，其余主动台词照旧静默。
> - 第 3 条比第 2 条更硬：全屏时**连观察类也不发** —— 气泡会浮在人家的游戏/演示/视频画面上。
>   游戏与会议只在"窗口化"时保留一句陪伴/观察，全屏一律安静。

### 7.4 台词库

- 位置：`assets/nurture/dialogues/{scene_id}.json`（用户可编辑、可增删、可扩充新场景）
- 结构（示例）

```json
{
  "scene": "feed_done",
  "tone": "gentle",
  "cooldown_sec": 0,
  "min_gap_sec": 0,
  "lines": [
    { "text": "……谢谢。", "weight": 3 },
    { "text": "唔，好吃。", "weight": 2, "tone": "proud" },
    { "text": "你居然记得我喜欢这个。", "weight": 1, "min_level": 250 }
  ]
}
```

- 支持占位符：`{level}`（称号）、`{streak}`（连签）、`{hour}`、`{app}`（前台应用的中性称呼，如"浏览器"）、`{min}`（连续工作分钟数）
- **防重复**：每个场景记住最近 5 条已用台词，不重复抽到
- **权重抽取**：按 `weight` 加权随机；`min_level` 未达成则跳过
- **兜底**：文件缺失/解析失败 → 用代码内 `DEFAULT_LINES` 兜底，并在日志记录；**绝不因为台词文件坏掉而崩溃**
- **多语言**：本期台词**仅中文**；界面文案走 `src/translations.py`（zh/en/ja 三语）。结构上 `lines` 可扩展为对象形式以便日后加语言，但本期不做

### 8.2 新增：前台窗口感知（`WindowMonitor`）

**Windows 实现**（沿用项目"零额外依赖 + ctypes"的风格，与 `audio_monitor.py` 一致，**不引入 psutil**）

```
user32.GetForegroundWindow()                    → hwnd
user32.GetWindowThreadProcessId(hwnd, &pid)     → pid
kernel32.OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, ...)
kernel32.QueryFullProcessImageNameW(...)        → 进程名（如 Code.exe）
```

> **实现补充（阶段 G）**：上表里的 `GetWindowTextW` 已在实现中**去掉** —— 分类只按进程名，
> 用不到标题，于是干脆不调那个 API（源码里 `grep` 不到，比"读到了不记"更硬）。
> 另加一条几何判定：`DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` +
> `MonitorFromWindow`/`GetMonitorInfoW`，判断前台窗口是否**盖满它所在那块显示器**，
> 通过第二个信号 `fullscreen_changed(bool)` 发出（全屏不是"应用分类"）。

- **轮询**：1000ms `QTimer`，边沿触发（仅当前台应用变化时发信号），与 `audio_monitor.py` 同构
- **输出**：`app_changed(app_key: str)`，其中 `app_key` 是**归一化分类**而非原始标题
- **归一化映射**：`assets/nurture/apps.json`，进程名 → 分类（`code` / `browser` / `game` / `meeting` / `media` / `unknown`）

**隐私约束（硬性）**

| 要求 | 说明 |
|------|------|
| 默认**关闭** | 设置里独立开关「允许她感知你在用什么软件」，需用户明确开启 |
| 不落盘 | 窗口标题、进程名**只存在于内存**，不写入任何文件、不进日志 |
| 不上报分类之外的信息 | 台词只能拿到 `browser` 这种粗分类，**拿不到标题原文** |
| 不做内容判断 | 不读窗口标题的文本内容，只做进程名 → 分类的查表 |
| 拖黑名单 | 用户可添加"不要感知"的进程名；会议/密码管理器等建议默认在列 |

> 落地情况（阶段 G）：五条全部有机器可查的保证 ——
> 默认关闭时**连监控对象都不创建**（不是"创建了但不生效"）；
> `app_changed` 的 payload 只可能是六个分类之一；
> 源码级扫描确认没有取标题的 API、没有 `print`/`logging`、没有以写模式打开文件。
> 黑名单命中返回 `unknown`，与"不认识的应用"**完全无法区分**（连"这是一款密码管理器"都不泄露）。
> 唯一额外读的是窗口**类名**，用于排除桌面/任务栏这类"本来就盖满屏幕"的系统外壳窗口。

### 8.3 新增：打字强度

- `InputMonitor` 增加**按键计数**（内部累加，不逐次发信号），暴露：
  - `key_count_total`：累计按键数（供打字量兑换）
  - `typing_rate()`：近 30 秒按键数（供 `detect_typing`）
  - `active_seconds_today`：今日累计活动秒数（供陪伴时长兑换）
- 计数线程安全：在 `pynput` 回调所在的 QThread 里写、主线程读，用简单原子计数或 `QTimer` 拉取即可（避免跨线程锁竞争）

## 10. 数据持久化

### 10.1 分离两处存储（重要）

| 内容 | 位置 | 理由 |
|------|------|------|
| **设置**（开关、阈值、映射） | `config.json` 新增 `"nurture"` 段 | 沿用现有 `deep_merge` 平滑升级 |
| **状态**（好感度、库存、签到记录、统计） | **`data/nurture.json`（独立文件）** | 状态是**高频变动**的运行时数据；塞进 config 会让现有 `save()` 的"部分更新合并"逻辑变得危险，且每次喂食都重写整个配置 |

> 项目已有 `data/clipboard.db` 的先例，`data/` 目录是既定的运行时数据位置。

### 10.2 状态文件结构

```json
{
  "version": 1,
  "affection": 128,
  "level_index": 2,
  "streak": 5,
  "last_checkin_date": "2026-09-10",
  "affection_gained_today": 6,
  "gifts_sent_today": 1,
  "tease_count_today": 2,
  "inventory": { "奶油面包": 3, "草莓蛋糕": 1, "玫瑰花": 1 },
  "daily": {
    "date": "2026-09-10",
    "active_minutes": 42,
    "key_count": 1830,
    "minutes_rewarded": 0,
    "keys_rewarded": 0,
    "hourly_bonus_count": 1
  },
  "flags": {
    "first_run_bonus_granted": true,
    "afk_bonus_date": "2026-09-08",
    "checkin_reminded_date": "2026-09-10",
    "last_hourly_date": "2026-09-10",
    "last_hourly_hour": 14,
    "last_event_date": ""
  },
  "stats": { "total_fed": 37, "total_gifts": 6, "total_checkins": 5,
             "first_run_date": "2026-08-01" },
  "used_lines": { "feed_done": ["……谢谢。", "唔，好吃。"] }
}
```

> `flags` 是**按日期记"今天做过了没"**的地方（时段问候、签到提醒、各彩蛋）。
> 实现上它只认代码里那张 `FLAG_DEFAULTS` 表 —— 表外的键读档时会被丢掉，
> 所以不能"按场景动态拼键名"。要加新的日期标记，就去 `src/nurture_store.py` 里加一行。

### 10.3 写入要求

- **原子写**：先写 `nurture.json.tmp`，`os.replace()` 覆盖，避免断电/崩溃导致存档损坏
- **容错读**：解析失败 → 用默认存档启动 + 把坏文件重命名为 `nurture.json.bad-{时间戳}`，**不静默丢数据**
- **写入时机**：状态变化后 **2 秒防抖**合并写一次；程序退出时强制写一次
- **跨天重置**：`daily.date != 今天` → 重置 `daily` 与各 `*_today` 计数
