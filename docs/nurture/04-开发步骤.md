# 开发步骤 — 养成高木同学（Nurture）

> 配套：`01-需求规格.md`、`02-技术方案.md`、`03-设计规范.md`。
> 遵循项目工作流：**每阶段结束后设暂停点，验证通过再推进**；每步只改 1–2 个核心文件；不跨阶段开发。

---

## 全局红线（每个阶段都要自检）

1. **默认服装（PNG）的所有交互行为零变化**——悬停挥手、点击弹功能面板、拖拽、设置
2. Q版原有的悬停害羞、长悬停问号、单击惊吓、双击生气→哭、打字/音频/静音、夜间睡眠待机、AFK 随机 **全部不退化**
3. `src/bubble_panel.py` **一行不改**（2026-09-10 **全局换肤**时改了：用户要求左右键面板与设置窗口
   也统一成这套视觉，见 `docs/03-设计规范.md` 第 2、3 节；养成系统本身仍然一行没碰它）
4. 任何外部资源（台词/配置/图标/动画）缺失 → **降级，不崩溃**
5. 每阶段结束：`python -m py_compile` 通过 + 更新 `devlog/YYYY-MM-DD.md`

### 阶段 G 已知偏差

| 偏差 | 说明 |
|------|------|
| 多了一个 `fullscreen_changed(bool)` 信号 | 全屏不是"应用分类"：同一个游戏窗口化 ↔ 全屏来回切时分类根本没变。塞进 `app_key` 会凭空多出一个 `"fullscreen"` 假分类，而 `nurture_model.is_focus_mode(fullscreen=...)` 这个既有参数正好等着一份真数据 |
| 「读不到 → unknown」拆成了两条规则 | 02 文档 4.7 同时要求"视为 unknown"和"不清空上次分类"，字面上是矛盾的。落地为：**连着 3 拍**读不到才降级成 `unknown`，不足 3 拍保持上次分类。抖动不换台，持续读不到（管理员进程、反作弊保护的窗口化游戏）不装懂 |
| 完全不读窗口标题 | 01 文档 8.2 设想的做法是"读标题、本地匹配"，但按进程名分类根本用不到标题 —— 于是连那个 API 都不调：源码里 `grep` 不到，比"读到了但不记"更硬。只额外读窗口**类名**，用于排除桌面/任务栏（`Progman`/`WorkerW`/`Shell_TrayWnd`），否则点一下桌面就会被当成全屏 |
| `detect_app_*` 五个场景都进了 `FOCUS_EXEMPT_SCENES` | 否则 7.2 与 7.3 打架：会议软件下"主动台词暂停"会把「在开会呀」永远压住 —— 而那正是它唯一的时机场合。裁定同 `detect_typing`：**就事论事的观察类放行**。但**全屏是更早、更硬的闸门**，连观察类也不发（气泡会盖在人家的画面上） |
| 台词里刻意不出现 `{app}` 占位符 | 01 文档 7.4 允许"前台应用的中性称呼"，但资产测试的 `test_detect_scenes_never_mention_content` 明确要求感知类台词**不落到具体内容**（「代码」「视频」都在黑名单里）。既然不能落到具体，就没有必要引入一份"分类 → 中文名"的映射表：少一个活动部件，也少一处隐私面。`{app}` 仍留在白名单里备用 |
| 窗口化 + 不认识的进程 → 她什么也不说 | 219 条进程名覆盖不到所有软件（真机实测：`bf6.exe` 不在表里）。这是**有意的**：分类表宁可漏也不能猜。全屏保护（几何判定）与进程名无关，所以游戏照旧不被打扰；想让窗口化的冷门游戏也有陪伴台词，把它加进 `apps.json` 的 `game` 即可 |
| 开着开关时**第一次**打开仍要重启 | `main.py` 只在启动时创建感知器（默认关闭 ⇒ 连对象都不存在）。关掉开关是**立即**生效的（`set_config()` 会停掉并清状态），打开则需要重启 —— 阶段 H 的设置页会在这条上给一句提示（`foreground_detection_active()` 就是为此准备的） |
| 全屏期间"有东西到手"的通知不拦 | 签到/兑换/彩蛋走的是 `_speak()`（用户挣来的交代，不是她主动找话）。全屏静默管的是"主动台词"，把奖励也吞掉会变成"我明明签到了她却不理我" |
