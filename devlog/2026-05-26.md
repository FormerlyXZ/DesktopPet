## 问题记录

| 问题 | 解决方案 |
|------|----------|
| Bash 终端无法运行需要 QApplication 的 Python 脚本（exit 127） | 语法级验证替代运行时验证；确认 Qt 对象需要在有 QApplication 的桌面环境中初始化 |
| audio_monitor 初版使用 comtypes 库作为依赖 | 重写为纯 ctypes COM vtable 调用，移除 comtypes 依赖 |
| GifCharacter 行为检测方法使用硬编码动作名 | 改为可配置字段 + get_settings/apply_settings 完整序列化 |
| **🐛 启动闪退：QMovie.setLoopCount 不存在** | PySide6 的 QMovie 无 `setLoopCount()` 方法。改用 `_looping` 标记 + `finished` 信号重播实现无限循环，`_play_once` 依靠 `finished` → `_on_movie_finished` 状态转换自然结束 |
| **🐛 GIF 所有动画无限循环（点头/摇头等不会回到待机）** | 所有 GIF 文件内建 `loop=0`（无限循环），QMovie.finished 永不触发，状态转换彻底失效。改为在 `_on_frame_changed` 中检测帧号归零（`frame_num==0 && _once_started`）来判定一轮播放结束，手动 stop + 调用 `_on_movie_finished` 触发状态转换 |
| **🐛 设置面板太窄，内容显示不全** | 窗口从 380×550 扩至 420×600 |
| **🐛 ComboBox 响应鼠标滚轮切换选项** | 为所有设置页 ComboBox 安装滚轮拦截器（eventFilter），滚轮事件仅用于滚动面板 |
| **🐛 设置中切换到Q版后，下拉框无任何动画可选** | `_on_settings()` 仅在 `char_type=="gif"` 时调用 `set_gif_actions()`，PNG模式下打开设置则GIF页下拉框为空。改为始终创建 GifRegistry 扫描素材库并填充所有下拉框 |
| **🐛 设置中切换角色类型后保存，桌宠不切换** | `_on_save_settings()` 只保存 config.json 但不重建角色。新增 `character_swap_needed` 信号 + `set_character()` 热切换方法 + main.py 中完整重建角色和监控器的处理函数 |
| **🐛 设置中从Q版切回PNG，PNG动画选项仍显示Q版** | `_on_settings()` 使用当前角色的 `get_available_animations()` 填充 PNG 页面（当角色为 GIF 时传入 GIF 动作名）。改为始终从 assets/ 目录创建 AnimationEngine 扫描 PNG 动画，与当前角色类型解耦 |
| **🐛 系统音频播放/静音时对应GIF未显示** | 根因层层递进：**(1)** vtable 索引全部错误 — `GetMute` 是 vtable[15] 而非 6(`SetMasterVolumeLevel`)，`GetMasterVolumeLevelScalar` 是 vtable[9] 而非 4(`UnregisterControlChangeNotify`)，`GetDefaultAudioEndpoint` 是 vtable[4] 而非 3(`EnumAudioEndpoints`)；**(2)** Windows `BOOL` 是4字节 `int` 而非1字节 `c_bool` 导致栈破坏；**(3)** 根本问题：纯 ctypes 手动 COM vtable 函数指针调用在 x64 Python 3.14 上持续 crash（Access Violation），即使 vtable 索引和类型都正确也无法工作。最终方案：使用 `comtypes` 库定义完整的 COM 接口类（IMMDeviceEnumerator, IMMDevice, IAudioMeterInformation, IAudioEndpointVolume），由 comtypes 自动管理 vtable 布局和方法分发。comtypes 方法将 `['out']` 参数作为返回值直接返回 |
| **🐛 打字优先级应高于音频** | `handle_key_press` 只在 IDLE 时触发，若恰好音频动画播放中则被忽略。改为：若处于 INTERACTING 且当前动作为音频类（唱歌/静音），允许打字直接打断并切换为打字动画 |
| **🐛 鼠标长时间停留只触发一次问号** | `_on_long_hover` 播放问号后 hover_timer 未重启。在 `_on_movie_finished` HOVER_IDLE 分支添加 `_hover_timer.start(LONG_HOVER_MS)` 重新计时 |

## 图片查看 Bug 深入修复（9-10）

### 🐛 9: 图片缩略图点击无法放大查看（第6次尝试）

**前5次失败总结**：
| # | 方案 | 结果 |
|---|------|------|
| 1 | `label.mousePressEvent = lambda` 直接调 `_open_image_viewer` | 无反应 |
| 2 | `installEventFilter` | 无反应 |
| 3 | QPushButton + `setIcon` + `clicked.connect` | 悬停有框，点击无效 |
| 4 | 卡片 `mousePressEvent` 位置检测 | 不行 |
| 5 | `label.mousePressEvent = lambda e: e.ignore()` 冒泡 | 不行 |

**根因分析**：PySide6 中通过属性赋值覆写 QLabel 实例的 `mousePressEvent` 不可靠；之前 eventFilter 尝试可能因缺少 QEvent 导入失败。

**最终方案**：
1. `_build_image_preview` 改为 `label.installEventFilter(self)` + `label.setProperty("image_path", path)`
2. 新增 `eventFilter()` 方法：检测 `QEvent.MouseButtonPress` + 读取 `image_path` property → 调用 `_open_image_viewer`
3. `_on_card_click` 简化为仅负责复制到剪贴板（移除位置检测逻辑）
4. 卡片 `mousePressEvent` lambda 不再传递 event 和 image_preview 参数

**涉及文件**：`clipboard_window.py`
- 新增 `QEvent` 导入
- `_build_image_preview`：installEventFilter 替代 lambda
- 新增 `eventFilter` 方法
- `_on_card_click`：简化为只做复制

### 🐛 10: 复制图片时可能被文字拦截

**根因**：`_on_debounced` 先检查文字再检查图片。浏览器等应用复制图片时会同时在剪贴板放置文字（URL/alt text），导致被误判为文字复制，图片被丢弃。

**修复**：调换检测顺序——先检查 `QClipboard.image()`，再检查 `QClipboard.text()`。

**涉及文件**：`clipboard_monitor.py`

## 图片显示重构（第10次方案变更）

### 背景
"缩略图 + 点击弹窗放大查看" 方案经过 9 次尝试，ImageViewer 窗口在 Windows 上始终无法正常渲染。根因定位为 `WA_TranslucentBackground` + `FramelessWindowHint` + `Tool` 窗口标志组合在 Windows DWM 下不兼容。

### 最终方案：面板内直接显示大图
**放弃弹窗路线**，改为在卡片中直接显示大图：
- 图片最大宽度 470px（面板内容区宽度）
- 图片最大高度 350px（防止长截图撑爆面板）
- 小图（≤470×350）使用原分辨率，不放大
- 大图等比缩放，`Qt.KeepAspectRatio` + `SmoothTransformation`
- 点击图片卡片 → 复制到剪贴板

│  2026-05-26 21:28:22         │
